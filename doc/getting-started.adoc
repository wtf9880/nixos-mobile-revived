This guide covers the common path for installing and customising Mobile NixOS.
The exact steps depend on your device, so keep its page handy:

* <<devices/index.adoc#,Supported Devices>>

== Before you start

These instructions assume you know how to prepare your device for development
use. The details are device-dependent, but they are not specific to Mobile
NixOS.

In short, the device's bootloader must be unlocked, meaning that it allows
running custom-built operating system images.

The project is hosted at
link:https://github.com/wtf9880/nixos-mobile-revived[nixos-mobile-revived].

== Install with the guided installer

For a limited set of devices, there is a guided installer that can be used to
do your first-time install.

The device page for the supported devices describes the requirements for the
installer.

* <<devices/pine64-pinephone.adoc#,Pine64 PinePhone>>

== Install manually

Use this path when your device does not have a guided installer, or when you
want to build and install the system yourself.

=== Getting the sources

Clone the repository, either over SSH or HTTPS:

```console
$ git clone git@github.com:wtf9880/nixos-mobile-revived.git
```

Or, for everyone else:

```console
$ git clone https://github.com/wtf9880/nixos-mobile-revived.git
$ cd nixos-mobile-revived
```

Nothing else is required; the build inputs are fetched by Nix.

If you want to test a device whose support has not been merged yet, check out
the relevant pull request branch. The
link:https://help.github.com/en/github/collaborating-with-issues-and-pull-requests/checking-out-pull-requests-locally[
GitHub help article] explains how.

=== Build and install

This is where a single guide cannot cover everything. These are different,
heterogeneous hardware platforms, with different quirks, compilation steps,
and installation steps.

Find your device on the <<devices/index.adoc#,supported devices>> page; its
page should contain the necessary instructions.

=== Using a known-good revision

Things change, and sometimes things break. This is even more true with Mobile
NixOS, since the project depends on another moving target, NixOS.

The Nixpkgs revision is pinned in `flake.lock`. It is updated from time to
time with `nix flake update`; breakage with `nixos-unstable` is a bug and
should be reported.

== Customizing

You will probably want to toggle options while experimenting with Mobile NixOS.
The repository is structured so that you can add options in an untracked
`local.nix` file. The default `nix-build` invocations use that file as your
configuration.

A sample `local.nix`:

```nix
{ lib, ... }:

{
  # Disables splash screens during boot
  mobile.boot.stage-1.splash.enable = false;
}
```

Because flakes only see files tracked by Git, `local.nix` must be tracked
(`git add local.nix`) when you evaluate the project through the flake. When
using `nix-build ./default.nix`, an untracked `local.nix` is used directly.

As Mobile NixOS is a superset of NixOS, all NixOS options can be used in this
configuration file. Note that most NixOS options only affect the stage-2
(rootfs, `system.img`) build.

The <<options/index.adoc#,options list>> gives an overview of all Mobile NixOS
specific options.

== Using in your system configuration

As the Mobile NixOS configuration may include fixes and quirks for your device,
it is useful to include it in your system's `configuration.nix`.

=== With flakes

Add this repository as a flake input, then import the device configuration
where you build your NixOS system:

```nix
{
  inputs.mobile-nixos.url = "github:wtf9880/nixos-mobile-revived";

  outputs = { self, nixpkgs, mobile-nixos, ... }: {
    nixosConfigurations.phone = nixpkgs.lib.nixosSystem {
      system = "aarch64-linux"; # or "armv7l-linux"
      modules = [
        ./configuration.nix
        # "xxx-yyy" is your device "Identifier" from
        # https://wtf9880.github.io/nixos-mobile-revived/devices,
        # e.g. "google-marlin".
        (import "${mobile-nixos}/lib/configuration.nix" { device = "xxx-yyy"; })
      ];
    };
  };
}
```

=== With `NIX_PATH`

Assuming your `NIX_PATH` includes `mobile-nixos=/path/to/nixos-mobile-revived`,
you can import the configuration directly:

```nix
# configuration.nix
{
  # "xxx-yyy" is your device "Identifier" from
  # https://wtf9880.github.io/nixos-mobile-revived/devices,
  # e.g. "google-marlin".
  imports = [
    (import <mobile-nixos/lib/configuration.nix> { device = "xxx-yyy"; })
    # ...
  ];

  # ...
  # Other configuration...
  # ...
}
```

While it is possible, directly importing configuration files from the
`examples` directories is discouraged. They may change in ways that break your
system configuration. Copy and edit the files from `examples` instead.
